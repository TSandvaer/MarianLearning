# Sibling-tier addition checklist

What this doc covers: the canonical list of every file + symbol that must change when adding a new sibling-tier node to the `WordSongNode` or `NumberGardenNode` union. Extracted 2026-05-14 from the PR #211 (digraph SkillNode split) audit: the original "five-place widening contract" referenced in `e2e/_helpers/wordSongNodesInOrder.ts:36-50` and `progress-and-persistence.md` was actually 13-plus places. This file is the canonical reference so future sibling-tier work doesn't have to re-discover the list.

This is a checklist, not a tutorial. Each row is **one literal you must add** when shipping a new tier (e.g. `cvc-words-short-e`, `digraphs-sh`, `mult-3-4-extension`). The intent column tells you _why_ the file matters so a reviewer can grep for it.

## Provenance

## What this list does NOT cover

The checklist is for the **node-shape contract** — adding a new tier to the curriculum tree. It does NOT cover:

- **Word/picture pool content** (`MarianLearning/src/screens/WordSong/wordPack.ts`, `wordDistractors.ts`, `wordPictures.tsx`, `_plannerWordList.ts` per-tier word lists). Those are the content tier's responsibility; they ride on top of the SkillNode infrastructure but are independently authored. The picture-pack pipeline (`design/word-song-picture-pack.md`) is the canonical reference for that side.
- **Per-tier prompt blocks** in `WORD_SONG_TRACK_GUIDE` (`api/_planner.ts:971-1097`). Required when adding first-class content; not required for infrastructure-only PRs.
- **Per-tier canon JSON files** in `public/canon/word-song/level-1/`. Generated by `scripts/generateSessionCanon.ts` once you add the tier to `WORD_SONG_FOCUS_NODES` (#15) AND ship first-class content. Commit the JSON alongside the code change per `project_canon_commit_strategy.md` memory.
- **`api/_firstEncounterGate.ts FIRST_ENCOUNTER_GATED_NODES`** — only edit if the new tier ships first-encounter scaffolding (a tier-specific opener line). Most tiers don't.
- **`WORD_SONG_GRADUATION_GATED_NODES`** in `mastery.ts` — explicitly does NOT widen for new tiers. Per `progress-and-persistence.md` § "Graduation gate", the set stays at `{ 'cvc-words' }` only; new sibling tiers are vocabulary-extension, not decoding-acquisition gates.
- **`CVC_CROSS_VOWEL_NODES`** in `mastery.ts` — widening happens in a separate cross-vowel-mix PR (see `cross-vowel-mix-spec.md`). Coordinate with the matrix-author when extending.
- **`substituteSentenceGap` (or any TTS-time text transform in `api/_tts.ts`)** — only for a "don't-say-the-answer" / display-only-token tier (cloze, fill-in). When the canon `read` carries a token that must NOT be voiced verbatim (e.g. `___`), the substitution lives in `_tts.ts` and is gated on `tierFilter === '<new-tier>'`. **Coupled to first-class membership (#14):** the transform only fires when `effectiveFocusNode` resolves to the new tier via `WORD_SONG_FIRST_CLASS_FOCUS_NODES`, so a tier missing from that set silently loses its audio transform with no error. There is no automated guard — the only catch is Thomas's ear-test. `simple-sentences` (PR #423) is the canonical reference; standard word-tap tiers don't need this.

## Sibling-spec audit (post-PR-#190 lesson, "Place 8" in the old contract)

Some e2e regression specs seed `'mastered'` up to tier N + `'practicing'` on tier N+1 to assert the focus-node picker lands on N+1. These tests are **invisible to typecheck**; they fail only at Playwright run-time. When inserting a new intermediate tier, audit ALL specs that target the post-CVC-graduation picker endpoint:

- `MarianLearning/e2e/cvc-cross-vowel-mix-regression.spec.ts` — tests 1 + 3 seed all CVC tiers `'mastered'` and assert the picker lands on the next non-CVC node. When you insert a new sibling tier between CVC and the asserted-on node, add it as `'mastered'` in the seed (otherwise the picker stops on your new tier instead of the asserted-on one).
- `MarianLearning/e2e/progression-mastery-loop.spec.ts` — the sight-words describe block has the same shape; same audit applies.

Per Kevin's PR #190 review audit (`46b9c9f`): all other CVC-tier-targeting specs are safe by construction (they target earlier tiers with `'practicing'`, so the picker stops there before reaching the new tier). Only the post-CVC-graduation specs are in the at-risk pattern.

The cleanest reference for what a sibling-tier addition looks like in practice:

## When in doubt

If you're touching a SkillNode-related file that ISN'T in this list, that's a signal — either:

1. The file is content/wordpack/picture-pipeline (not in scope; see the "What this list does NOT cover" section), or
2. The list is missing an entry. **Document the find in your PR description and add the row here in the same PR.** Future-you will thank you.

The 14-place audit took two real PRs to settle. Maintenance is the only way the list stays accurate.
