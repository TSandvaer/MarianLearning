## Console / network sanity

## E2E framework recommendation

The brief asks me to flag whether E2E framework setup is now warranted as a separate ticket. **My recommendation: yes, open a ticket — but as planning/spike, not "ship Playwright in this sprint."**

Reasoning:
- We now have 2 screens shipped (Splash, Greet-stub) and a 3rd in active impl. The manual desktop column on this checklist is already 21 rows long (20 AC bullets + the first-utterance pending-state row 8b that PR #15 introduced); the survival checks add 13 more. That's a 30-minute manual pass per PR that touches Greet, repeated for every future PR. By Screen 5 we're easily at 90 minutes of manual-only regression per release.
- AC rows 7 and 20 (the gesture-unlock rows the entire ticket exists for) cannot be meaningfully validated in unit tests — they need a real browser. Right now I'm proposing static-analysis hacks (parsing handler source for `await` tokens) which are brittle. A Playwright test on real WebKit would assert the actual `onstart` latency under Safari rendering.
- Survival checks like rage-tap, background/resume, mid-animation tap, and the 5-min relock recovery are tedious to do manually and high-value to catch in CI. They're textbook E2E scenarios.
- Cost is real: Playwright/Cypress setup + WebKit channel + CI integration is ~1–2 days of Devon or Kevin's time. Not a sprint-killer but not free.
- Counterargument: shipping by August 2026 is the goal. Every day spent on test infra is a day not spent on Math, Word Song, Reward. If the manual checklist can carry us through Screens 3–5 and we automate after first end-to-end run, that's defensible.

**My call:** flag to Matt and Thomas as a planning ticket. Decision they should make: "do we set up Playwright before Screen 4, after Screen 5, or after Session 1 end-to-end ships?" My weak preference is "before Screen 4" because Screens 3 and 4 add the math and literacy state machines, which are exactly the kind of stateful flows where manual QA misses regressions. But Thomas owns the call.

In the meantime: **this checklist is the right scope for the current ticket**, and `qa/splash-regression.md` plus this file are the source of truth for manual passes.
