# Native app with no Claude API: sizing

**Question (Thomas, 2026-10-23):** what does a store release of the native app take if it never calls the Claude API, and every session is built on the device from a baked pool per step?

**Scope:** the native app (`mobile/`) and `@marian/core`. The frozen web keeps `/api/claude` as it is. Sizing only: no code changed, no paid calls, no renders. Dave is sizing the pedagogy in parallel (`design/research/no-claude-variety-2026-10-23.md`, branch `dave/no-claude-variety`). His doc landed during this sizing (`a10c2c7f`), so § 3 prices his pool sizes (Number Garden 366, Word Song 425) as scenario D. It also gives 2× and 4× today's pool and "every fact" on the closed steps, plus a per-step cost per item.

**How the numbers were made:** a scratch script read all 45 canon files under `public/canon/`, ran each line through the production text transform `renderElevenLabsText(text, tier)` (`api/_tts_elevenlabs.ts:157`), the exact string ElevenLabs bills per character (`design/voice-migration-elevenlabs.md:19`), and deduplicated on that string, as the Lily render does (`scripts/revoiceCanonLily.ts:12-13`). A second script generated every fact of the closed steps from the planner's own templates and the curated fact pools in `scripts/compositionLint.ts`. For the facts already in canon it reproduced every existing line exactly (0 misses across 10 steps), so the generated lines are the lines a bake would produce.

## Summary

- Only **4 learner paths** reach Anthropic from the native app. Each is a canon-bypassing hint on the one session-start request. All four can be served on the device: the vowel map needs no new audio, the graduation check's first 4 probe words are already rendered (Dave asks for a reserve of 12), and the two math hints get their full value once the math pools grow (phase 5a).
- Every session, canon hits included, is still a network request to `/api/claude`. The server also refuses every session when `ANTHROPIC_API_KEY` is unset, before it even looks up canon (`api/claude.ts:758`). So "no Claude" means the app stops calling `/api/claude`. Removing the key from the server would break sessions.
- Core can already compose a whole session from canon blocks using the Leitner box: the times mix does it (`pickMixBlocks`, `packages/core/src/progress/reviewPlan.ts:522`). The on-device builder generalises that picker and moves the server's block copy (`api/_review.ts`) into core.
- Bundling today's canon audio adds **24.2 MB** (deduplicated). New Lily characters at **Dave's pool sizes ≈ 35,500**, which means ≈ 1,540 ear-test rows and ≈ 30 MB. For comparison: 2× pool ≈ 26,200, 4× pool ≈ 76,500, and every fact on the 9 closed math steps 7,386. Today's whole canon is 29,066.
- **6 phases**, plus the graduation PR already in flight. After phases 1–4 the app makes no `/api/claude` call and can go to the store with today's variety. Phase 5 grows the pools.

## 1. Inventory: where the native app reaches Anthropic

There is one call site: `startSession` POSTs `{ kind: 'session-start' }` to `/api/claude` (`mobile/src/audio/sessionStart.ts:31`, `:97`). Its callers are Math (`mobile/src/session/mathSession.ts`), Word Song (`mobile/src/session/wordSongSession.ts`), the Map peek and replay (`mobile/src/session/peekSession.ts:205`) and a debug check (`mobile/src/audio/debug/audioCheck.ts:177`). The other two request kinds, `stumble-explanation` and `session-end` (`packages/core/src/wire/types.ts:10`), only get the legacy stub and the native app never sends them.

The server answers from canon (free) unless `bypassCanonAndCache` (`api/claude.ts:972`) is true. Then it logs a canon miss (`:1064`), applies the rate limiter (`:1076`) and runs Haiku plus a live ElevenLabs render (`generateSessionStartResponse`, `:1100`). If a hinted request has not finished after 5 s on screen, the app re-requests without the hints and gets canon (`mobile/src/session/sessionStartFallback.ts:19`), so all four paths below are best-effort today.

**What the app would still use the server for**

- **Canon serving.** Every canon hit, review, peek, replay, times mix and warm-up is a `/api/claude` round trip today, and the response carries ~1.7 MB of base64 (`sessionStart.ts:11-12`). Review, peek, replay and mix cost nothing on the server: the client picks the blocks and the server copies them (`api/_review.ts:1-48`). Phases 1–2 move all of this onto the device.
- **TTS of non-canon lines.** This only happens on the Haiku path (`claude.ts:1100`). No other live TTS reaches the app. Once paths 1–4 are local, there is none.
- **`/api/progress`.** Cloud backup and the launch reconcile (`packages/core/src/progress/cloudSync.ts:76`; `mobile/src/screens/parentSettings/parentSettingsDeps.ts:121`, `:140`; `mobile/src/lifecycle/launchReconcile.ts`). Both are optional and turn off when `EXPO_PUBLIC_PROGRESS_API_SECRET` is unset (`mobile/src/platform/buildEnv.ts:13`). A store build has to decide whether to keep them, because the secret ships inside the bundle ("casual-abuse protection, not real auth", `buildEnv.ts:28-30`).

**Can canon and audio ship bundled? Yes.** Today's canon is 45 files with 3,028 utterances. They contain 1,342 unique request texts, 29,066 unique Lily characters and **24.2 MB** of unique MP3 (51 MB as stored, because the per-file copies repeat lines). The app's bundled audio is 16 MB today (`mobile/assets/audio`, 814 files). There is a precedent: `export-audio.mjs` already decodes every blend clip out of the canon and bundles it (`mobile/scripts/export-audio.mjs:15-19`). The app has no `expo-updates` (`mobile/package.json`), so a bundled pool grows only with a store release. Serving the static `public/canon/**` files instead (`api/_canon.ts:19-28`) is possible, but bundling is what makes sessions work with no network.

## 2. The on-device session builder

**Where it lives.** A new pure module, `packages/core/src/session/composeSession.ts`, sits next to `reviewPlan.ts`, whose pickers it generalises. A mobile adapter, `mobile/src/session/localSession.ts`, returns the same `PreparedSession` that `startSession` returns today (`sessionStart.ts:48`): `plan`, `currentTargetVowel` and `audio`. The plan adapters (`mathSessionPlanFromServer`, the Word Song round adapter) and the screens stay unchanged.

**Inputs**

- **The step pool.** One canon file per step with N problems instead of 8. A generated fact table per block, like `CANON_MATH_FACTS` (`scripts/generateCanonMathFacts.ts`), lets the picker choose math blocks by fact.
- **The progress doc.** `mathFactsLeitner` (`LeitnerBox`, `packages/core/src/progress/types.ts:213`), due items (`dueLeitnerItems`, `leitner.ts:174`), slow facts, `letterSoundsVowelStates`, the graduation flag, `lifetimeFirstEncounters` (which drives the first-encounter opener) and the warm-up / review / mix kind (`sessionPlanKind`, `reviewPlan.ts:374`).
- **A per-learner seen-record per item:** last day, count and last result (Dave § 2.1 rule 5). This is a new progress-doc field, so it needs a migration and a guard like every other one (`packages/core/src/progress/migrate.ts`, `guards.ts`), and it travels in the cloud blob.
- **A seed and the clock.** The seed is the session count at kick time and the clock is the progress clock, exactly as the review picker uses them today (`reviewPlan.ts:22-24`), so the Hub prefetch and the tap build the same session.

**Output.** The plan comes out in today's wire shape, `ServerPlan { id, label, utterances[{id, text}] }` (`packages/core/src/math/planFromServer.ts:252`). Picked blocks are renamed `math|word.p1..p8.<slot>`, warm-up blocks `w<i>`, plus the step's `session.end.*` lines and the same plan-id prefixes the server uses (`review-`, `peek-`, `replay-`, `mix-`; `_review.ts:16-48`). Audio comes as one bundled module per line. That needs a `bundled` variant of `AudioRef`, which the wire type already anticipates (`packages/core/src/wire/types.ts:41-42`), and a load path that plays bundled files instead of writing base64 to disk (`mobile/src/audio/sessionAudio.ts:162`).

**How the picker rules plug in**

1. **Math** (Dave § 2.2), built by generalising `pickMixBlocks`. Slots 1–3 are known facts. Slots 4–8 take due box-1/2 facts first (cap 3, shared with the warm-up), then at most 2 new facts, then due box-3–5 facts, then the lowest box. 1–2 slow facts go in where the old directive applied. Dave also changes the session end so that a fact promotes at most once a day, and only when it was due (`packages/core/src/sessionEnd/progressHistory.ts:653-659`).
2. **Words** (Dave § 2.3): least-recently-read first, at most 4 of 8 shared with the previous session, never the same order, and 1–2 earlier-vowel words in slots 4–8 from short-o on.
3. **Composition rules move from the prompt into code.** Today they are enforced only by Haiku's self-checks at bake time plus the bake-time lint (`.claude/docs/planner-and-canon.md:219`, `:225`). The curated pools and rules already exist as data in `scripts/compositionLint.ts` (`SUB_TO_TEN_POOL` `:378`, `ADD_TO_TEN_RULES` `:907`, … `LETTER_NAMES_RULES` `:4746`). Move them to core and require every composed session to pass the lint, with a property test over many seeds and progress docs.
4. **Word Song:** port the deterministic post-Haiku passes (`reorderContinuantOnsetFirst`, `pinCvcRecapFocus`; `planner-and-canon.md:169`). The vowel map works as in § 1 row 3. The graduation check follows Dave § 2.4: 6 probe words across two sessions, a pass at 5 of 6, and a disjoint 12-word reserve per learner. It skips any word that learner has already met, the Play place included.

**How a pool grows.** Add problems `p9..pN` to a step's canon file. Math lines come from a deterministic template generator (the scratch generator above), so a bake needs no Haiku. Word items come from Dave's word list plus a picture per word; the app bundles 122 pictures today (`mobile/assets/pictures`). Then render with `revoiceCanonLily.ts --unrendered` (`:21-23`), ear-test on `/voice-qa.html?filter=new`, run `export-audio`, and release. Three code seams widen with it:

- `mathSessionPlanFromServer` reads problems 1–8 by default (`planFromServer.ts:271-278`). The builder renames picked blocks to p1–p8, so the adapter is untouched.
- `CanonBlockRef.problem` is documented as 1..8 (`reviewPlan.ts:65`) and widens to 1..N.
- The voice-QA page's `CANON_FILES` list is hardcoded (`public/voice-qa.html:649`).

**What can ship first.** Phases 1–2 are pure engineering with no ear-test, and 1 → 2 → 4 are the shortest route to a build with no Claude call (3 can land alongside). Phase 5a is the cheapest content win and Dave's first priority. **Risks across the plan**

- The device now composes every session that Haiku used to compose, so the composition rules must hold every time. The property test in phase 3 is the gate.
- The binary grows by 24 MB, then about 30 MB for Dave's pools.
- Dave expects first scores to drop below today's 100% with bigger, mixed pools. That is expected, not a regression (his Risks section).
- Without `expo-updates`, pool growth ships only in store releases.
- Ear-test load scales with new lines, and Thomas is the gate (Predict-Before-Soak applies to 5a–5c).
- New word items are gated on pictures.
- The cloud-sync secret needs a decision before a public store build (§ 1).
